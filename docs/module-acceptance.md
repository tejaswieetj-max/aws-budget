# Per-module “Done when” acceptance tests

This is the acceptance checklist; a listed condition is not claimed complete unless the test/evidence exists.

| Module | Done when |
|---|---|
| M0 Foundation/DevOps | Clean Python 3.12 environment installs dependencies; lint/tests run; CDK synthesizes offline; config and outputs are documented. |
| M1 Identity/access | Cognito PKCE sign-in/team claims work; each Lambda has a least-privilege role; ProvisionerRole has an ap-south-1 EC2-only permissions boundary; hosted UI domain prefix and localhost plus optional CloudFront callback/logout URLs are parameterized. `scripts/verify_m1.py` covers tagged assume-role and four DryRun launch cases but is human-run and remains unverified until executed in an AWS account. |
| M2 Data/ledger | Five exact-key tables are locally synthesized with Reservations team/creation and status/expiry GSIs, Budgets/Reservations PITR, and idempotency-only TTL. Moto tests cover budget and reservation state transitions, invariant preservation, duplicate/conflicting idempotency, insufficient and concurrent reservations, safe workflow-unknown release rejection, settlement retries/corrections/overruns, and indexed queries. A separate approved integration run verifies conditional transactions, contention, GSI behavior, TTL, and IAM against real DynamoDB. |
| M3 Pricing | Fixture/provider tests cover supported SKUs, product/dimension selection, Price List pagination, missing/conflicting prices, in-memory and seven-day DynamoDB cache expiration, fallback provenance, and upward integer-micro-USD rounding. Reservations persist snapshot ID and fetched-at. `scripts/verify_pricing.py` prints the three required live comparisons for a human to run. A live Mumbai Price List snapshot remains unverified until that script is run and compared with AWS Pricing Calculator. Estimates identify compute and gp3 storage separately and document exclusions. |
| M4 Admission | A verified identity from the auth adapter is required; team mismatch is denied; fixed 1.10 reserve is rounded up; team/period/idempotency are passed to the atomic M2 ledger; duplicate and conflicting key behavior, insufficient budget, concurrent admissions, and ambiguous outcome reconciliation pass unit/Moto tests. No workflow starts before durable confirmation. The five-minute invariant checker recomputes ledger totals with consistent scans, rechecks once before alerting, writes a de-duplicated Alert, publishes InvariantViolation and emits EMF. Admission emits decision/latency EMF and records estimate/provenance/shadow margins. An explicitly isolated, opt-in naive experiment demonstrates oversubscription and refuses without its flag. Live JWT/team authorization, DynamoDB transactions/contention, and route integration are verified separately and are not claimed by local tests. |
| M5 API | All nine routes are wired to a Cognito JWT-authorized API Gateway HTTP API v2 and distinct least-privilege Lambda roles. Local handler tests cover v2 claims, response envelopes/statuses, developer/admin groups including string-form groups, team isolation, M4 idempotency/pending outcomes, M2 reads/writes, and M7 asynchronous cancellation dispatch. CDK synthesis verifies route/authorizer/stage shape; live Cognito/API Gateway/IAM verification remains separately required before deployment. |
| M6 Orchestration | Standard workflow starts only after a durable hold; deterministic execution identity and unknown-start recovery are durable; restricted ProvisionerRole uses reservation/team STS tags; EC2 request has no public IP/key pair/ingress, uses approved SKU/gp3, ownership tags, encrypted delete-on-termination volume and IMDSv2; workflow waits/polls, records instance/volume IDs and activates; tag-scoped failure cleanup is idempotent; controlled pre-launch injection safely releases. Confirmed terminal failure plus COMPLETE cleanup settles a versioned prorated runtime amount and returns unused reserve atomically; partial/unknown cleanup remains held and alerted. Local Moto/fake tests and CDK synthesis pass; live execution/IAM/network verification remains required. |
| M7 Lifecycle | Activation creates a deterministic one-time expiry schedule; a five-minute safety sweeper recovers missed expiry and retries incomplete cleanup; cancellation conditionally transitions ACTIVE to CANCELLED and dispatches the same reaper. Reaping verifies ledger instance and all ownership tags before termination, deletes only recorded owned volumes after termination, and provisionally settles the full reserve only after cleanup is confirmed. Duplicate schedules/events and out-of-order state notifications are idempotent. Unknown workflow/resource state and cleanup failures leave funds reserved; stable alerts are written. CloudTrail RunInstances bypass detection publishes BypassDetected alerts, and the daily orphan audit is read-only. Local Moto/fake tests and synthesis must pass; scheduler delivery, EC2 termination/deletion, CloudTrail, IAM and EventBridge behavior remain live-unverified. M8 final billing correction is not part of this module. |
| M8 Billing | S3 manifest notifications invoke a dedicated disabled-by-default reconciler; schema-validated Athena query is period-filtered and uses the scan-limited workgroup. Decimal-to-micro-USD conversion, charge classification, exact tag/resource attribution, unattributed handling, duplicate rows, revision deltas, ledger/audit atomicity, concurrent replay and invariant preservation pass fixture/Moto tests. CUR export/table creation remains manual. Actual CUR field names, manifest/revision semantics, tagging, Athena/IAM behavior and billing results require VERIFY in an account before enabling. |
| M9 Calibration | `research/evaluate.py` validates operator-exported reservations plus M8 billing audit rows, joins by reservation ID, selects a unique latest revision and outputs explicit exclusions. Decimal/integer-micro metrics, candidate margins with upward rounding, chronological holdout when enough periods exist, deterministic JSON/Markdown reports, fixed/rolling/split/adaptive synthetic comparisons, deterministic atomic/naive and feedback-lag experiments have local tests/artifacts. Current input contains no verified live observations; export provenance is operator-asserted. Local experiment latency/cleanup signals remain unavailable. Live results are not claimed. |
| M10 Web | React/TypeScript source implements PKCE Cognito hosted UI auth, all existing API routes, six required views, request idempotency retry retention, loading/error/empty states, private S3 + CloudFront/OAC synthesis and configuration outputs. API/idempotency client has Node tests. Browser-level component/accessibility tests and login flow remain unverified. Build dependency installation was blocked in this environment; `frontend/dist` was therefore not generated, so the CDK asset-deployment custom resource is intentionally omitted until `npm run build` succeeds. Do not deploy the incomplete static asset stack. |
| M11 Observability | EMF and structured JSON logging cover admission, budget utilization, workflow start/EC2 launch, lifecycle cleanup, billing, pricing and API-native signals with bounded metric dimensions. Dashboard, alarms for invariant, workflow, EC2 launch, cleanup, billing, API 5xx, invariant DLQ and 50/80/100% utilization, existing log retention, and an unsubscribed SNS topic synthesize locally. No X-Ray tracing is enabled; SNS has no recipient; budget samples are emitted only on new admissions; CUR lag has no alarm without a verified baseline. Live metric extraction, alarm states and notification delivery remain unverified. |
| M12 Test/demo/teardown | Local/integration/concurrency/failure suites, repeatable demo, tag-scoped dry-run teardown, and post-run EC2/EBS inventory are evidenced. |
