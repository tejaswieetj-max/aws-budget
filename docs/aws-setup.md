# AWS setup and approval boundary

Before any cloud change: enable MFA, use an individual IAM Identity Center/least-privilege identity, configure the AWS CLI profile locally (never send credentials), confirm account and `ap-south-1`, inspect AWS credits and service quotas, configure personal AWS Budgets notifications at 50%, 80%, and 100%, and check regional service availability. Those account/billing changes require the user's direct action/approval.

Bootstrap CDK only after reviewing its IAM/cost implications. Run synthesis and review the complete diff first. Before deployment, enumerate S3, CloudFront, Cognito, DynamoDB, Lambda, API Gateway, Step Functions, Scheduler, Glue/Athena, SNS/SQS, CloudWatch and other billable resources. Obtain explicit approval before deployment, any EC2 launch, billing export/tag activation, budget changes, or destructive cloud operations. `make synth` is local, writes the assembly to ignored `cdk.out/`, and directs the JSII package cache to ignored project-local `.cache/jsii/` using `JSII_RUNTIME_PACKAGE_CACHE_ROOT`; it does not contact AWS. `make test` must never call AWS mutation APIs. The deployment is not currently performed or verified.

Controller-launched instances must use private networking without NAT gateway or public IPv4, no inbound rules or key pair, IMDSv2, and tagged EBS with DeleteOnTermination. Before creating cloud resources check account credits and quotas. After approved tests, verify EC2 instances and EBS volumes by required ownership tags and confirm cleanup. Do not delete billing export data in ordinary teardown.

M6 synthesis defines required `PrivateSubnetId` and `ProvisioningSecurityGroupId` parameters. Before any separately approved deployment, verify that the subnet route table has no NAT gateway or internet route and that the selected security group has no ingress. The stack does not create a VPC, subnet, NAT gateway, or security group and does not perform these live checks for you.
